# 运行时开销排查与优化

2026-09-29，在 Apple M2 / macOS 上使用本地 Godot 4.7.2 `template_debug` 修复版。基线为 `f9f7379`，保存在独立项目中；前后使用相同基准，串行交替运行三轮，关闭 profiling 后计时。[全部运行数据](timings.json)。

## 主要原因和修改

1. **路径验证重复检查同一批障碍。** `_static_segment_clear` 已经对整段路径检查建筑矩形和资源圆，随后又逐点调用完整 `can_occupy`。现在逐点阶段只检查地形，保留建筑边界、资源擦边和重叠脱困规则。初始 400 人编队 profiling 中，90 步有约 62 万次占位检查；A* 本身累计只有约 15 ms，主要耗时在外围几何检查。
2. **局部避障网格重复扫描邻域。** 最宽恢复网格有 37,249 个格点，原来每格分别查询地形、建筑、资源和单位。现在复用静态几何栅格化，再按附近单位的覆盖范围填入障碍。驻军不参与地面碰撞；已有重叠允许向外移动的规则保持一致。
3. **空间查询范围过宽。** 原碰撞查询按所在桶向四周扩展整圈，小单位也通常扫描九个桶。现在只访问碰撞范围实际覆盖的桶，减少字典查找和邻居遍历。
4. **无关的资源移动触发所有小队重新寻路。** 编队原来遇到导航版本变化就无条件 `_replan`。现在清除几何缓存，验证剩余路线及各成员终点；路线仍有效时保留。空路线、受阻路线和调整过的目标仍会重新评估。诊断窗口循环时，曾观察到 34 个小队每帧重算，以及一次约 2.7 秒的落点搜索。
5. **寻找落点时做了多余的准备和搜索。** 不要求可达性的查询延迟创建通行网格。全地图兜底改为距离从近到远检查，找到第一个可达点即返回，避免按行扫描过程中对越来越近的多个点反复寻路；等距离仍按原来的行、列顺序选择。

没有降低碰撞精度、减少寻路搜索范围或降低模拟更新频率。新增 `move_step`、`recover_building_overlap` 和 `path_around_units` 可选计数，默认关闭。

## 三轮对照

以下每一项取三轮中位数，单位为毫秒。编队基准为 400 人、34 个小队、90 个 1/30 秒模拟步；独立移动为 400 人、180 步；战斗为 200 对 200、90 步。这些是 CPU 场景基准，不包含完整的 UI、AI 和窗口渲染，不能直接换算成游戏 FPS。

| 指标 | 修改前 | 修改后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 编队集中下令 | 157.1 | 123.1 | 22% |
| 编队平均模拟步 | 77.6 | 53.0 | 32% |
| 编队 P95 | 160.6 | 92.8 | 42% |
| 编队最大模拟步（各轮最大值的中位数） | 1145.6 | 642.4 | 44% |
| 独立移动平均模拟步 | 5.61 | 4.03 | 28% |
| 独立移动首次模拟步 | 207.62 | 71.92 | 65% |
| 战斗平均模拟步 | 2.77 | 2.78 | 基本不变 |

`performance_400.gd` 固定全局随机种子；地图种子仍为 4242。延迟创建导航对象会改变依赖实例 ID 的避让次序，因此这里比较同一场景，不声称逐步轨迹完全相同。战斗各轮均为 1,204 次攻击、14,448 生命损失、400 个幸存单位。

## 正确性验证

- 静态和动态栅格共 76 组、654,352 个位置，与独立的实际占位判定逐格比较，覆盖水陆、阵营、体型、偏移网格、地图外区域、单位／资源重叠和驻军。
- 新增编队回归覆盖远处资源移动不重算、路线和槽位保留、新建筑强制绕行、空路线重试、目标受阻及清障后的恢复。
- 新增全地图落点兜底回归，检查最近可达点及等距离选择顺序。
- 完整导航回归的 17 个脚本全部通过，退出码为 0，无脚本错误或断言失败。[结果记录](regressions.json)，通过 `tools/check_navigation.py` 可重跑。

少数脚本仍有退出时 ObjectDB 回收警告。原版本施工测试也会报告该警告；本次对经济测试的 `--verbose` 抽查显示残留对象为 `AudioStreamWAV` / `AudioStreamPlaybackWAV`。这次没有修改音频生命周期，也没有把这些警告计为已解决。

## 仍存在的限制

400 人密集编队平均 53 ms/步，仍未达到项目的 40 ms 目标。本次三轮中最慢一步为 1061.9 ms；同步精细搜索、复杂拥堵和集中重试仍可能造成卡顿。有窗口的密集移动诊断也出现长帧，本次没有取得完整、可比较的真实窗口 FPS 结果，不能宣称已经消除卡顿。

迷雾单次更新仍约 14 ms，导航障碍和空间索引仍会整体刷新。后续应优先测量并处理每帧搜索预算和障碍局部失效；本次将修改集中在已确认的重复工作上。

## 重跑

```sh
python3 tools/check_navigation.py
RTS_BENCH_STEPS=90 python3 tools/check_navigation.py --tests performance_400 performance_navigation performance_combat
RTS_NAV_PROFILE=1 RTS_BENCH_STEPS=90 make run RUN_ARGS='--headless --script res://tests/performance_400.gd'
```

窗口基准 `performance_visible.gd` 同时修正了投影选择：按实际当前视角决定是否切换，避免用户保存的 2.5D 设置使结果标签与实际画面相反。
